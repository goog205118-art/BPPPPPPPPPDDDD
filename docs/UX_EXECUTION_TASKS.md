# 工作台 UX 重构执行台账

## 文档职责

本台账是“资源库工作台信息架构与桌面 UX 重构”的唯一执行入口。它独立于已完成的 `CRM_EXECUTION_TASKS.md`：不重复、替换或改写 CRM 能力，只调整用户看到的入口、层级、默认视图和操作密度。

- 建立日期：2026-09-13
- 当前里程碑：信息架构与日常工作入口重构
- 数据原则：不读取或修改正式业务资料；不连接真实 IMAP、SMTP、AI 或线上存储进行视觉验证。
- 交互原则：保留现有人工确认、AI 审核、品牌隔离、邮件安全与保留控制；界面改造不得弱化这些边界。

## 状态与记录规则

| 状态 | 含义 |
| --- | --- |
| `planned` | 需求已登记，尚未进入实现。 |
| `active` | 正在实现或验证。任何时刻只允许一个核心任务处于此状态。 |
| `blocked` | 有外部阻塞，须记录恢复条件。 |
| `done` | 已通过对应验收和回归验证，并记录提交号。 |
| `deferred` | 已确认推迟，须写明重新评估条件。 |

1. 实现前先将最小可验证工作项设为 `active`，并追加阶段日志。
2. 每个小阶段结束后必须追加日志，记录文件、验证、提交和下一门槛。
3. 功能提交与台账检查点提交分开，检查点提交引用功能提交。
4. 上下文恢复时，先读取“当前执行指针”和最后三条日志；不得凭聊天历史重新规划或重复已完成步骤。
5. 所有行为改动后至少运行 `npm.cmd run check`；影响既有 CRM 页面时，补充相关专项回归。
