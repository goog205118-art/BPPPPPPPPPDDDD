# 多品牌官邮与 AI 跟进执行清单

更新时间：2026-08-31

## 本轮目标

将已经进入达人库的合作对象，按品牌隔离为可持续跟进的工作区。用户可连接多个品牌官方邮箱、同步近期邮件摘要、在网页中根据真实上下文获取 AI 中文分析与英文回复草稿，并在人工确认后通过 SMTP 发送。

## 当前边界

- [x] 跳过定时同步、定时 AI 判断和定时推进阶段
- [x] AI 不自动改变合作阶段；邮件规则仅允许“等待回复”进入“初步沟通”，不回退后续阶段
- [x] 不读取或保存邮件附件
- [x] 不因 AI 建议直接推进阶段，需人工确认或使用手动快捷推进
- [x] Foxmail 导入为追加写入；保存失败恢复导入前页面状态，不覆盖其他品牌事件
- [x] 邮件摘要可升级为完整纯文本正文；旧截断正文可被后续完整正文替换

## 实施清单

- [x] 数据结构增加品牌、邮箱账户、邮件正文与账户关联字段
- [x] 本地 API 支持多品牌、多邮箱、IMAP 测试/同步及 SMTP 测试/发送
- [x] Vercel API 与本地 API 使用同一套邮件处理模块，并已核对请求与响应路径
- [x] AI 设置增加“邮件分析与跟进回复”能力分配
- [x] 顶部增加可切换品牌工作区；达人、产品、跟进、邮箱账户和邮件记录按工作区隔离
- [x] 设置页支持新增、编辑、测试、同步和删除多个品牌官方邮箱
- [x] 跟进详情面板展示邮件时间线、关联产品、物流、当前阶段和内部备注
- [x] AI 输出中文状态摘要、证据范围、风险提示、推荐下一步和建议跟进间隔
- [x] 用户选择策略并填写中文意图后，AI 生成可编辑、无签名的英文回复草稿
- [x] 官方邮箱账户支持保存自定义文字签名和图片签名；本地图片通过 CID 内嵌到 SMTP 邮件，默认邮箱客户端复制时携带富文本图片，AI 不负责生成签名
- [x] SMTP 发信同时发送标准化纯文本和 HTML 正文：统一字体、段落间距、链接短标签和产品链接超链接
- [x] 默认邮箱客户端备用路径复制同一份带签名富文本；由于 `mailto:` 不能可靠预填 HTML，仍需用户在邮箱编辑器中粘贴后发送
- [x] 待开发达人开发邮件可选择当前品牌官方 SMTP 邮箱，确认后真实发送，并记录首发事件
- [x] SMTP 首发成功后自动建立正式 `followUp`，初始保存 `lead_id` 为“已联系待回复”；回信自动转入达人库、补齐 `creator_id` 并进入“初步沟通”
- [x] Foxmail / 官邮同步到唯一匹配的外部首发邮件时，同样建立“已联系待回复”正式跟进；已有达人库活跃跟进的外发邮件直接归档到该跟进
- [x] 待开发达人打开系统默认邮箱客户端并标记已联系时，也会按同品牌 `lead_id` 建立或复用“已联系待回复”跟进和联系轨迹；复用旧的“待开发 / 待回复”记录时会推进到“已联系待回复”，已经进入初步沟通、协商或寄样等后续阶段的记录不会倒退；该入口只记录人工联系意图，不伪造 `mail_sent`，实际发信后仍需同步已发送邮件
- [x] AI 开发邮件在没有可用 SMTP、改为打开默认邮箱客户端时，也会先保存“已联系待回复”；保存失败不会打开邮箱，避免再次出现已联系但看板无记录
- [x] 跟进进入“已结案”时幂等沉淀合作记录，并关联 `follow_up_id`、品牌、达人和产品
- [x] 结案联动将达人状态更新为“已合作”，已有“沉淀”状态时不覆盖
- [x] 没有可用 SMTP 时保留复制并打开系统邮件客户端的备用路径；保存“已联系待回复”成功后才跳转，保存失败会回滚且不会跳转；备用路径不会伪造已发送事件
- [x] 待开发达人未绑定品牌时，联系入口会阻止保存并恢复原状态，避免只写入“已联系”却没有合作跟进
- [x] Foxmail `.eml` 导入补齐品牌与邮箱账户元数据
- [x] 在隔离存储目录完成写入与 API 回归；不连接真实邮箱、不发送真实邮件

## 本次验证结果

已于 2026-08-31 在临时存储目录运行：

```powershell
npm.cmd run check
npm.cmd run test:followup-isolation
```

两项均通过，另已通过 Python AST 与 Git 空白检查。隔离回归覆盖：

1. 两个品牌可各自保存达人、产品、合作跟进、收件箱摘要和同一外部邮件标识，互不覆盖。
2. 两个品牌可各自保存官方邮箱；接口只返回配置状态，不回显 IMAP 或 SMTP 密码。
3. 未配置 AI 时，沟通分析和英文草稿都会明确失败，且不会改动跟进阶段。
4. 选择另一品牌的官方邮箱发送时，服务端会在建立 SMTP 连接前拦截请求，不新增邮件时间线，也不改动阶段。
5. 线程邮件通过 `References` / `In-Reply-To` 续接时，达人入站回信会保留“待处理新回复”高亮；明确处于等待回复语义的跟进会进入“初步沟通”，合作协商中的跟进不会倒退，已结案、暂停跟进和未谈妥不会自动重开。
6. 邮件正文缓存兼容中文布尔值，摘要升级完整正文、截断正文升级完整正文、完整正文不被普通重复同步覆盖，以及超过 10 封邮件的全量摘要/最新正文优先逻辑已通过隔离回归。
7. 待开发达人首发跟进生命周期已通过回归：SMTP/外部已发送邮件建立等待跟进，回信线程转入达人库，且不会在首发时提前创建达人。
8. Foxmail 导入确认使用完整状态快照，导入只追加到全量邮件事件；跟进达人显示优先稳定 ID，结案合作记录优先 `follow_up_id`，旧 `cooperation_id` 仅在同品牌且唯一时回用。

## 仍需人工配置验证

下列步骤依赖真实服务，故没有在本次代码验证中执行：

1. 为每个品牌录入各自的 IMAP/SMTP 服务地址、邮箱账号和授权码，并先点击连接测试。
2. 在 AI 设置中为“邮件分析与跟进回复”指定已配置的模型，再用一条真实或脱敏邮件摘要检查中文判断与英文草稿质量。
3. 发送前逐项核对收件人、主题和正文；确认提示后先向内部测试邮箱发送一封测试邮件。
4. 线上部署时在 Vercel 配置访问密码、凭据加密密钥和持久化存储；SMTP 出站是否可用仍须以服务商实际测试结果为准。

## 安全与数据边界

1. AI 仅从 `followUpId` 反查同品牌的达人、产品和最近邮件事件，忽略前端伪造的邮件内容；完整正文并非无限保留，受缓存授权、期限、单封长度和总上下文预算控制。
2. IMAP/Foxmail 同步邮件默认只保存摘要；AI 会标记“仅基于已归档摘要”。SMTP 在本系统发出的邮件可保存完整正文，并标记为“已发送正文”。
3. 未被邮件或人工资料明确提供的信息必须保持未知，不得推测报价、地址、寄样、发布日期或合作承诺。
4. SMTP 发信前必须显示确认提示；所选官方邮箱必须属于该跟进记录的品牌。
5. 邮箱授权码使用 AES-256-GCM 加密存储，接口只返回是否已设置，绝不回显密码。

## 验收标准

1. 可新增两个不同品牌，并且在任一工作区中不显示另一品牌的数据。
2. 可保存两个官方邮箱账户，账号与品牌绑定；测试 IMAP/SMTP 和同步时明确作用于选定账户。
3. 邮件时间线能区分 IMAP/Foxmail 摘要与系统 SMTP 已发送正文。
4. AI 分析与草稿生成不会自动改变任何跟进阶段。
5. 待开发达人通过 SMTP 发送需用户二次确认，成功后建立一条首发 `mail_sent` 记录、正式 `followUp` 和 `waiting_reply` 轨迹；外部同步首发邮件也必须进入同一链路。
6. 跟进推进到“已结案”后只生成一条对应合作记录，合作记录可回溯到来源跟进。
7. 线上 Vercel 与本地服务调用相同的请求/响应结构。
8. 邮件账户签名可保存、回填并在 SMTP 发信与默认邮箱客户端复制路径中一致追加；AI 草稿中即使出现常见签名行，也不会重复发送两份签名。

## 部署提示

Vercel 函数的 SMTP 出站连接可能受到服务商端口或网络策略限制。优先使用 TLS 端口 `465` 或 STARTTLS 端口 `587`，并始终先点击 SMTP 测试；测试通过前不将线上 SMTP 视为可用。
